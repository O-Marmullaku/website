# Marmullaku website

## Local development

Serve this directory with `python -m http.server 8000 --bind 127.0.0.1` and open http://localhost:8000/.

On localhost, every profile opens with inline editing. CV drafts, uploaded files and sample links stay in this browser; they do not read or change live CVs. Drafts use the `marmullaku-local-profiles-v1` browser storage key, separate from the mockup. Local sample links include `?local=1` and work only in the browser holding their data.

Public hosting always uses the normal authenticated backend. Ordinary company invitation links on localhost also use that backend unless marked as local sample links. The local mode accepts only loopback hostnames, not LAN addresses or domains.

CV and settings transitions are shared in `main/profile-motion.mjs`. The outer window keeps the editor visible while drafts flush and the exit animation completes; the frame is removed afterward.

The reader and inline editor share the white A4 presentation in `main/cv-paper.css`, layered over editor and live-window styles. The paper is centered independently; extras open from Links & documents in a side drawer at every width. Preview lists only documents without a link on the paper; Edit retains the complete file library. CV actions float at the upper right as compact light controls (Links & documents, plus round download and close buttons with tooltips) and step aside while a PDF is open. The CV stays centered when documents open. Supporting PDFs open in a right sidebar with their own download action, filling phone screens. The panel slides and fades in; the rendered page fades in once ready. A light black shade (26%) fades over the CV behind the open PDF and lifts as the reader closes; it never takes clicks or focus. The sidebar itself stays transparent: one dark sheet in its upper right holds a header attached directly above the page, and grows only as tall as the page plus a little padding, scrolling inside once the page is taller than the screen. The header shows the title, a page stepper (Previous, page count, Next), a view group (zoom out, zoom level, zoom in, fit toggle), then download, maximize, and close, separated by spacing and a single rule above the page. Narrower readers give the title its own line with the window actions and put page and view controls on the line below, instead of shrinking or scrolling the controls. Maximize expands the reader inside the page; Restore returns it to the right sidebar. Escape restores a maximized reader before closing it, and closes directly on phones. Zoom re-renders the PDF at a minimum of two bitmap pixels per displayed pixel. Clicking a page (or pressing Enter when it is focused) shows a wide 1.6× reading lens centered on the cursor and rendered directly from the PDF; clicking again, leaving the page, scrolling, or changing pages dismisses it. The lens stays below the PDF controls, fades in on entry, and completes its fade-out before hiding. Files that cannot be rendered can be downloaded for a PDF app. The preceding layout is preserved at Git tag `checkpoint/cv-toolbar-before-full-height-pdf-2026-10-23`; its local comparison is `/work/cv-toolbar-baseline/#osman`.

`main/profile-bridge.js` opens `/profile/`, whose loader waits for styles before starting the canonical `profile/editor.js`. `profile/editor.html` supplies its template; direct navigation redirects through the homepage. Both `/` and `/mockup/` use this editor. The mockup swaps account services for browser-owned sample data, with separate storage. Keep both attachment database names when changing storage, so existing uploads remain readable. Backend setup is documented in [supabase/README.md](supabase/README.md).

After changing `index.html`, regenerate its mockup counterpart with `node mockup/sync-homepage.mjs`.

## Checks

Run `node --test tests/*.test.mjs` for the unit suite. Browser checks are the four `tests/*.browser.mjs` scripts; run them against the local server. They use Playwright (or the module URL supplied in `PLAYWRIGHT_MODULE`) and Firefox (optionally supplied in `FIREFOX_EXECUTABLE`). The full-site check also accepts `CHROMIUM_EXECUTABLE` to run in Chrome. It uses isolated synthetic profiles and blocks live backend requests, covering both homepage routes at desktop and phone widths, inline edits, close/save behavior, project panels, attachments and PDF rendering.
